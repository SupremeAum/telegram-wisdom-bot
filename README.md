# Афиша Усть-Каменогорска — полуавтомат

Бот собирает события городской афиши, рисует к каждому карточку и готовит
текст поста. **В канал ничего не уходит без явной команды** — публикация
всегда через отдельный шаг с подтверждением.

Здесь же живёт прежний бот с цитатами (`bot.py`).

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python fetch_fonts.py     # шрифт Inter для карточек

cp .env.example .env      # вставить токен от @BotFather
python -m afisha.cli check
```

## Команды

| Команда | Что делает |
|---|---|
| `python -m afisha.cli check` | Диагностика: токен → канал → права → тестовый пост |
| `python -m afisha.cli draft` | Собрать события, отрисовать карточки, сложить в `drafts/` |
| `python -m afisha.cli list` | Показать готовые черновики |
| `python -m afisha.cli publish` | Опубликовать утверждённое в Telegram (спросит подтверждение) |
| `python -m afisha.cli wa` | Выгрузить посты для WhatsApp-канала в `outbox/whatsapp/` |
| `python tests.py` | Прогнать тесты |
| `python fetch_fonts.py` | Скачать шрифт Inter для карточек |

Полезные флаги: `draft --days 7 --limit 5`, `publish --yes --limit 3`,
`publish --only 2026-09-05`, `check --no-post`, `wa --all --limit 5`.

## Рабочий цикл

```
                            ┌→ publish  →  Telegram (автоматом)
draft  →  просмотр  →  ─────┤
                            └→ wa       →  outbox/whatsapp/  →  вставить руками
```

Утром `draft` собирает афишу и складывает черновики. Ты просматриваешь
карточки, лишнее удаляешь (просто стираешь `.json`), затем `publish`
отправляет в Telegram, а `wa` готовит то же самое для WhatsApp.

## WhatsApp

**У каналов WhatsApp нет официального API.** Meta его не даёт: постить
может только админ из приложения. Поэтому `wa` не публикует, а готовит —
кладёт в `outbox/whatsapp/` пару файлов на каждый пост:

```
01-08-28-vecher-organnoy.txt   текст в разметке WhatsApp (*жирный*)
01-08-28-vecher-organnoy.png   карточка
README.txt                     порядок постов
```

Открываешь канал, прикладываешь картинку, вставляешь текст. Тридцать
секунд на пост, ноль риска для номера.

Текст под WhatsApp собирается отдельно, а не конвертируется из
телеграмного: у площадок несовместимая разметка (HTML против `*жирный*`),
и при конвертации HTML→WhatsApp неизбежно теряются ссылки.

Когда объём станет болезненным, сюда добавляется отправка через
[WAHA](https://waha.devlike.pro/) — self-hosted HTTP API. Он нарушает
ToS WhatsApp и ставит номер под риск бана, поэтому только с отдельной
SIM и только когда ручная рутина реально мешает. Интерфейс `afisha/whatsapp.py`
под это уже готов: менять придётся один последний шаг.

## Картинки: постер источника или своя карточка

**По умолчанию берётся официальный постер события.** Организатор рисует
афишу яркой именно для того, чтобы на неё посмотрели и пришли, — репост
ему выгоден. А лента из одинаковых сгенерированных градиентов читается
как машинная и обесценивает канал.

Своя карточка — запасной вариант: когда постера нет или он не прошёл
проверку. `draft` показывает, что откуда:

```
✓ 28.08 19:00  Вечер органной музыки          [постер]
✓ 30.08 18:30  Спектакль «Ревизор»            [карточка]
```

Отключается флагом `PREFER_SOURCE_POSTER=0`.

### Что отсеивается (`afisha/poster.py`)

- меньше 400px по стороне — это логотип площадки или превью-заглушка;
- пропорции вне диапазона 0.4–2.6 — баннеры и полосы ломают вертикальную ленту;
- битые файлы и не-изображения.

Постер **не кадрируется**: обрезка съест имя артиста или дату. Он
вписывается целиком в формат 1080×1350, а поля добираются размытой
копией его же — фон получается в цветах самого постера.

## Своя карточка

Рендерит `afisha/card.py`, шрифт Inter (OFL). Шрифт в репозитории не
хранится — ставится один раз через `python fetch_fonts.py`. Если его нет,
рендер не падает, а откатывается на системный DejaVu.

**На изображении только латиница.** Русские названия транслитерируются:
«Вечер органной музыки» → `VECHER ORGANNOY MUZYKI`. Кириллица в
декоративных начертаниях часто ломается — кривой кернинг, отсутствующие
глифы. Весь русский текст живёт в подписи к посту, где с типографикой
всё в порядке.

Палитра выбирается по категории события (концерт / театр / выставка /
детям / вечеринка), так что лента выглядит как один бренд.

Посмотреть формат, ничего не публикуя:

```bash
python make_samples.py     # результат в samples/
```

Данные в `make_samples.py` вымышленные, поэтому результат кладётся в
`samples/`, а не в `drafts/` — команда `publish` его не подхватит.

## Источники

`afisha/sources.py` — ticketon.kz и sxodim.com. Падение одного источника
не роняет запуск: ошибки ловятся пер-источник.

Вёрстка афиш меняется без предупреждения. Если `draft` перестал находить
события — селекторы вынесены наверх каждого парсера, чинится одной правкой.

Дедупликация по нормализованному названию и дате: одно событие в трёх
афишах даст один пост. Из дублей выбирается запись с более полными данными.

## Что было сломано в прежней версии

Канал не публиковал ничего по четырём независимым причинам:

1. `TOKEN = os.getenv("7143553038:AAE...")` — в `os.getenv` передаётся
   **имя** переменной окружения, а не значение. Возвращался `None`,
   `Bot(token=None)` падал на старте.
2. `CHANNEL_ID = "@t.me/prosvetlyaka"` — невалидный `chat_id`. Нужен либо
   `@username`, либо числовой `-100…`.
3. **Планировщика не существовало.** `post_quote()` вызывался только из
   обработчика `/post`. Автопубликации не было в принципе — канал и не мог
   постить сам.
4. `from aiogram.utils import executor` — API aiogram 2.x, на 3.x это
   `ImportError` на этапе импорта.

Плюс `requests` в асинхронном обработчике блокировал event loop.

Всё это исправлено. Цитаты и афиша разведены по разным каналам:
`QUOTES_CHANNEL_ID` для `bot.py`, `TELEGRAM_CHANNEL_ID` для афиши —
иначе цитата Будды встанет между концертом и выставкой. Автопостинг
цитат по умолчанию выключен (`POST_INTERVAL_HOURS=0`).

## Безопасность

Токен раньше лежал прямо в коде (`bot.py`) и попал в историю git.

**Шаг 1 — отозвать токен, это важнее всего.** @BotFather → `/mybots` →
выбрать бота → `API Token` → `Revoke current token`. Пока токен не
отозван, им может воспользоваться любой, кто видел репозиторий. Чистка
истории этого не заменяет: GitHub держит старые объекты в кеше и отдаёт
их по прямой ссылке на коммит даже после force-push.

**Шаг 2 — вычистить токен из истории.** Локально:

```bash
git clone https://github.com/SupremeAum/telegram-wisdom-bot && cd telegram-wisdom-bot

FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch --force --tree-filter '
  [ -f bot.py ] && sed -i "s/7143553038:AAE6zb78AiVbS8zHpgNeltw_jnWJKiCEGWU/TELEGRAM_BOT_TOKEN/g" bot.py || true
' --tag-name-filter cat -- --all

git for-each-ref --format="%(refname)" refs/original | xargs -n1 git update-ref -d
git reflog expire --expire=now --all && git gc --prune=now

git push --force origin main
```

Секреты теперь берутся только из `.env`, который в `.gitignore`.
